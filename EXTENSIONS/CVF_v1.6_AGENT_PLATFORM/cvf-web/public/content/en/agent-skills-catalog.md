# Agent skill catalog

[Browse the skill library](/skills) to see the packages listed for agents and read the usage limits of each entry. A catalog entry does not grant permission to run a package.

If you want to describe a result, choose a [template on Home](/home). It helps you write a specification for the work. Agent packages and Home templates have separate catalogs.

## Describing an application change

Explain who uses the application, what they need to do, and how to verify that the change works. For an interface or data change, include examples of valid inputs and the expected behavior when information is missing. Record any access limits and identify the checks needed before release.

## Preparing integration and release work

Name the environment, owner, allowed changes, review steps, and recovery plan. If the work needs an external service or a connection to another system, identify the data it may receive and the person who approves the connection. For media, specify the expected format and what the reviewer needs to check.

## Supplying context and investigating problems

Share the minimum information needed to do the work and identify confidential sources. For a problem report, give the expected result, the actual result, and steps to reproduce it. Ask the agent to verify the likely cause before proposing changes.

## Planning work with an agent

Give the agent a clear goal, the sources it may use, and an example of the result you expect. If the task needs several steps, agree on a point to review the first result before continuing. Ask for links to sources and identify decisions that need your approval.

## Preparing a workflow for an agent

For research or a document conversion, name the input files and the expected output format. For repeated work, record what starts the work, how to tell it succeeded, and where to stop if a step fails. If several agents share the work, identify who verifies the final result.
