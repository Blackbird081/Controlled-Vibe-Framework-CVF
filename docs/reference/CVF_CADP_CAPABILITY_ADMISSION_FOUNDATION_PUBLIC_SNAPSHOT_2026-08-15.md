## Accepted Bounded Value

The private provenance lane has accepted an internal foundation with these
source-backed responsibilities:

1. deterministic capability admission, assignment, distribution, compatibility
   evidence validation, and receipts;
2. repository-backed owner/grant authority instead of caller-asserted truth;
3. pre-execution eligibility projection for the Execution Plane;
4. provider-neutral constraint projection for the Model Gateway;
5. transport-neutral external-readout validation, allowlisting, redaction,
   freshness evaluation, and deterministic receipts;
6. fail-closed authentication and literal-false authorization composition;
7. drift checks across owner, contract, consumer, and package-export surfaces.

The resulting internal chain is:

```text
repository authority
  -> capability admission
  -> owner binding
  -> execution eligibility
  -> provider-neutral constraints
  -> bounded readout preparation
```

## Demand-Gated Reopen Policy

External CADP runtime expansion is parked, not pending. Reconsideration requires
all of the following in a fresh governed tranche:

1. a current non-test consumer;
2. a concrete blocked workflow or operator-visible outcome;
3. an authoritative metadata and authorization owner independent of caller
   claims;
4. a bounded receipt or operator destination;
5. positive base and sensitized value-cost margins of at least `+12`;
6. explicit operator approval for the smallest viable surface.

Agents must treat CADP as a validated architectural foundation, not as an
available public endpoint. They must verify callable source paths in the
checkout before claiming runtime use and must not create a transport surface
without a fresh governed tranche satisfying every reopen condition.
