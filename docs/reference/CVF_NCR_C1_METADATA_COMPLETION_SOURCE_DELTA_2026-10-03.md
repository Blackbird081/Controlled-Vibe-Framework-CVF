## O1, Attempt Policy And O3

Source facts read at the lock version in D107 and rechecked for presence at the hub head: the Hub client resolves a default-revision lookup offline from refs/main and the snapshot pointer after a blocked metadata call, and the request hook raises before sending. The blocked call is still a library-level request attempt. D108 F-03 therefore forbids a zero-attempt promise for O1.

| Policy | What it asks | Route | Status |
|---|---|---|---|
| P0 strict zero library Hub requests | no request attempt of any kind, blocked or not | O3: minimal codec_dir forwarding or an upstream change (no fork here); local backbone directory plus onnx_dir already avoid the other sites | not chosen; O1 does not satisfy it |
| P1 blocked attempts logged, no socket egress | pre-send blocked requests recorded as attempts and a separate no-successful-host log | O1 with offline flag and staged cache (flag set before import, refs and file hashes verified outside the library) | not chosen; needs an explicit separate approval |

No policy is chosen, no default exists, and O2 reimplementation stays disfavoured. Operator decision OD-03 selects the policy; DM-04 and DM-05 are the planned proofs.

### Enforcement strategies

| Strategy | Hard bound? | Limitation |
|---|---|---|
| Fixed-size volume or virtual disk used as the target root | yes, set by the operating system | needs operator setup and privileges; cannot cap RAM; only bounds the target volume |
| NTFS disk quota on the target volume | yes, per user on that volume | privileges; other locations (home cache, OS temp) are outside it unless redirected |
| Polling directory-size watcher | no | overshoot = poll interval x peak write rate + largest single write unit; both unmeasured, so overshoot is UNKNOWN until a bounded probe measures it |
| Per-download Content-Length check and abort | network phase only | header is a declaration; says nothing about unpacked size |
| Cleanup inventory and process-tree stop | not a bound | removes partial files and orphan processes after a stop; needs before and after listings |

Proposal: admit preparation only with an OS allocation bound or an operator-stated bounded overshoot; a watcher alone cannot certify a cap. Exact choice is operator-owned (OD-07).
